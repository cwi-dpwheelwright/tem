# Testing Program (Iteration 02)

This file defines repository-wide testing conventions and gating expectations.

## Test layers
- Unit tests: fast, deterministic, component-level.
- Integration tests: service dependencies and contract flows.
- Smoke tests: minimal boot and health checks.
- Simulation tests: fault injection and degraded dependencies.

## Evidence
- Store reports under `artifacts/` with timestamps.
- Include test commands and artifact paths in iteration notes.

## Conventions
- Tests must be deterministic (seeded randomness and controlled clocks).
- All contract changes require updated fixtures and gold tests.
- CI should fail on codegen drift and contract mismatch.

## Gold test suites (pytest markers)
- `smoke`: basic gateway routing + health checks (budget: < 2 minutes).
- `integration`: live dependency flows (budget: < 5 minutes).
- `simulation`: fault injection and degraded dependency scenarios (budget: < 10 minutes).
- `e2e`: full happy-path service workflows (budget: < 10 minutes).
- `negative`: deliberate invalid inputs and error contract checks (budget: < 5 minutes).
- `contract`: schema/fixture contract validation (budget: < 1 minute).

## Recursive learning gates
- Recursive validation run evidence must match `contracts/json-schema/recursive_validation_run.json`.
- Controlled ASK E2E cases are defined in `testing/recursive-intelligence/controlled-ask-e2e-suite.v1.json`.
- Results and stakeholder reports are generated by `testing/recursive-intelligence/run-controlled-ask-e2e.py`.
- Production-like recursive ASK E2E runs should authenticate through identity first: set `CWI_BASE_URL`, `CWI_IDENTITY_USERNAME`, and `CWI_IDENTITY_PASSWORD`, then run `python testing/recursive-intelligence/run-controlled-ask-e2e.py --execute --auth-mode identity`. Standard tenant-scoped users also require `CWI_IDENTITY_TENANT_ID`; pre-issued bearer tokens may use `--auth-mode token` with `CWI_AUTH_TOKEN`.
- The controlled recursive ASK suite starts through `/api/ask`. If `/api/ask` returns deferred home-node work instead of a final answer, the runner polls `/api/ask/deferred/{work_id}?request_id=...` for final ASK output before grading. Unresolved deferred work is graded as `UNKNOWN_HOME_NODE_DEFERRED_UNRESOLVED`, not as proof that recursive intelligence passed or failed.
- A recursive ASK E2E report is behaviorally valid only when `NOT RUN` is `0`. Any `NOT RUN > 0` artifact is an execution-attempt diagnostic, not quality evidence.
- Hard governance gates are zero-tolerance: pack trust, frozen trace fields, approval gating, provenance ledger, kill-switch, tenant isolation, privacy/OPSEC, and rollback.
- Quality thresholds are evaluated only after hard governance gates pass.

Runner example:
- `python tools/cwi-gold-tests/run_tests.py --suite smoke --base-url http://localhost:18081`
- `python tools/cwi-gold-tests/run_tests.py --suite smoke --base-url http://localhost:18081 --junit-xml artifacts/gold-tests/junit.xml --json-summary artifacts/gold-tests/summary.json`
- `python tools/cwi-gold-tests/run_tests.py --suite contract --junit-xml artifacts/gold-tests/contracts.xml --json-summary artifacts/gold-tests/contracts.json`
Reconciliation gold tests can target orchestrator directly:
- `CWI_RECON_BASE_URL` (e.g., `http://localhost:18085`) overrides `CWI_BASE_URL` for reconciliation endpoints.

## ETL integration test secrets
The ETL ingest integration test is env-driven. Set these in CI to enable it:
- `CWI_ETL_INGEST_URL` (e.g., `http://cwi-router:8081/api/ingest/document`)
- `CWI_ASK_URL` (preferred) and optional `CWI_ASK_PAYLOAD_JSON`
- `CWI_VECTOR_SEARCH_URL` (fallback if ASK is not set)
- `CWI_VECTOR_SEARCH_PAYLOAD_JSON` (required for vector search)
- `CWI_TRACE_LOOKUP_URL_TEMPLATE` (optional, uses `{trace_id}` token)
